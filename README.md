# Swing Desk

Rules live in the Engine Rules document, code and architecture in the Code and Architecture document, scope in the Scope of Work document. This repo is public (from 22 Oct 2026, so GitHub Actions minutes are unlimited). Nothing personal (capital, holdings, trades, account files) may be committed anywhere in it: `scripts/check-no-personal-data.mjs` enforces that under `data/` and `fixtures/` and fails if any file under `portfolio/` is tracked. The owner's saved accounts and the holdings book live in the separate private repo `bpishigh/swing_desk_portfolio`; the nightly workflows check it out at `.portfolio-repo` and link its top-level `portfolio/` folder as `portfolio/` (both ignored by git here) using the `PORTFOLIO_TOKEN` secret, and the Worker reads and writes it through its `REPO` setting.

## Names used in this project
- **Repo Desk**: this repository and the site it publishes. The TypeScript engine, the nightly GitHub jobs, JSON data, the Portfolio Manager and the alerts.
- **Claude Desk**: the older desk on Claude Artifacts, to be wound down once the Repo Desk matches it.

## What it does today
- **Site** (`site/`, served by Cloudflare Pages behind Access): the desk tabs (Market, Funds, Scans, Paper test, Engine Rules, Docs) and the Portfolio Manager (`site/upload.html`). `site/pm/*.js` and `site/pm-data/` are built copies made by `scripts/build-pm-site.mjs` from `src/pm/*.ts` and the public data.
- **Nightly data** (India and US): described in the two sections below, run by the half-hourly tick.
- **Scan and paper book**: the nightly screen writes `data/india/scan/latest.json`; the paper book IND-PAPER-1 (`scripts/paper-book-india.mjs`) keeps three streams (official, capwaived, comparator) in `data/india/paper/latest.json`. Only official picks are orders; the other two are a test and live on the Paper test tab (C-113).
- **Portfolio Manager**: broker files are read in the browser; accounts are saved to the private repo through the Pages Functions in `functions/` (`/api/portfolio`). Trades can also be added by hand between monthly uploads and are reconciled on the next upload (C-114).
- **Nightly sized orders** (`scripts/sized-shortlist.mjs`): runs the saved accounts through the same pipeline and sizing as the page and sends two Telegram messages, the official orders and the paper test, each only when its text changed. Results are written to the private repo, never here. `scripts/holding-alerts.mjs` sends exit alerts for open trades.
- **Rules**: every rule and code change is first a row in the Engine Rules change log. Where a document and the code disagree, the side that is latest and accurate wins (C-79).
- **Tests**: `node --test test/*.test.ts` (not bare `node --test`, which runs research scripts and rewrites `data/`).

## Alerts and probes
- Alert channel: Telegram (`scripts/alert.mjs`).
- `scripts/source-test.mjs` probes candidate data sources from GitHub's servers and appends to `data/source-test/log.ndjson`; `scripts/summarise-source-test.mjs` prints the verdict per source.
- Scheduling runs from `.github/workflows/tick.yml` (about 20 seconds: starts due jobs, alerts, writes the daily Actions-minutes estimate), started every 30 minutes by cron-job.org because GitHub's own cron fired too rarely. `source-test.yml` is the older probe-plus-dispatch workflow, kept until cron-job.org points at the tick; see [docs/SCOPE.md](docs/SCOPE.md).

## Repo Desk India data (runs by itself every session day)
- **When.** The half-hourly `source-test` run (started by cron-job.org) also runs `scripts/dispatch-nightly.mjs`. From 19:00 IST on a session day it starts `india-nightly` and `india-stocks` for that day if either is behind, skips one that is already running, retries every half hour (20 tries per job per day), and sends one Telegram alert if the day is still missing at 22:30 IST. A missed day is caught up the next time (the stock job fills missed sessions). State: `data/india/orchestrator.json`. Both workflows can still be run by hand.
- `india-nightly` (`scripts/india-nightly.mjs`): NSE index close file -> `data/india/idx_closes.json`, `feed/latest.json`, `feed_hist/<date>.json`, `tracker/<date>.json`, `last-run.json`. 21 indices plus India VIX.
- `india-stocks` (`scripts/india-stocks.mjs`): NSE all-stock file -> one compact file per session in `data/india/bhav/`, and `stocks/latest.json` with close, volume, 50/200 SMA (through the session before D) and 10/20 EMA for every EQ/BE stock. No holdings or watch-list are stored: the file covers the whole market and the app filters.
- **Corporate actions.** A one-day move beyond 22% is a break; averages that straddle an unexplained break are left out. Breaks are explained, in order, by: a typed override (`data/india/corp-action-overrides.json`), an NSE circular (face-value split or ISIN sub-division, read from the PDF, cached in `data/india/circulars.json`), a published 200 DMA solved from Dhan (`corp-action-derived.json`), or NSE's corporate-actions list (`corp-actions.json`). Every factor must leave a one-day change within 20% or it is not applied. Each stock record lists what it was adjusted for (`adjustedFor`); `corporateActions` in `stocks/latest.json` lists resolved, unresolved and accepted-as-real breaks.
- **NSE file hosts.** `archives.nseindia.com` answers 404 for a file that does not exist; `nsearchives.nseindia.com` answers with a "not accessible in your region" HTML page instead. The jobs treat that pair as "not published yet".

## Repo Desk US data (runs by itself: daily after the close, screen on Saturdays)
- `us-nightly` (`scripts/us-nightly.mjs`): SPY, QQQ and the 14 sector ETFs from Tiingo (raw close plus the split factor Tiingo publishes on each ex-date) -> `data/us/eod/<T>.json`, then `tracker/<date>.json` (SPY with QQQ as `b`, plus `vix`), `feed/latest.json` and `feed_hist/<date>.json` (sectors: close, 50/200 SMA, 1- and 3-month return), `closes.json`, `last-run.json`. Same shapes as the Claude Desk's `us_tracker`, `us_feed`, `us_feed_hist`.
- **Method.** Closes are split-adjusted from Tiingo's split factors; dividends are not adjusted (as on a TradingView chart). SMAs include the day itself and are left out when fewer closes exist or a window crosses a 22% break. Each day's close is checked against StockAnalysis (0.1%); a ticker that disagrees is not written for that day and keeps its previous values with their own date. VIX is Cboe's close (FRED cross-checks the previous day).
- **Against the Claude Desk (2 Oct 2026).** Closes, 50 SMAs and 1/3-month returns are identical for all 14 sectors, SPY and QQQ. 200 SMAs match to the cent where the Claude Desk computed them from stored closes and run up to 1.7% higher where it used TipRanks (dividend-adjusted, lower). SPY volume is Tiingo's consolidated figure (46.34M vs StockAnalysis 45.46M on that day).
- **Schedule.** The half-hourly tick (`scripts/dispatch-us.mjs`, rules in `src/ingest/us-plan.ts`) starts `us-nightly` from 17:30 ET when the feed is behind (up to 8 tries per day, one phone alert after 22:30 ET), and `us-screen` from Saturday 08:30 IST once the feed holds the last session (one alert after 12:00 IST if it is not done). State: `data/us/orchestrator.json`. The calendar holds 2026 holidays only; 2027 must be added before January.
- **Backup price source.** If Tiingo is at its hourly limit or down, both US jobs fall back per ticker to Nasdaq's public history (no key, split-adjusted, same consolidated volume). Tested on 10 Oct 2026: the whole screen (38 stocks, every metric) and the daily job (16 tickers, no conflicts with stored bars) come out identical to the Tiingo run. Yahoo (HTTP 429) and Stooq (403) refuse GitHub's servers. A run that used the backup says so in its flags.
- **Breadth and regime alert.** Breadth = share of the index above its 50-day average: India uses the Nifty 500 (NSE's list) from the stored daily files (`scripts/breadth-india.mjs`, run by `india-stocks`); the US uses the S&P 500 from Nasdaq's public history (`scripts/breadth-us.mjs`, workflow `us-breadth`, started by the tick after each close). Checked against the figures typed into the Claude Desk: US 29 Sep 24.6 (typed 24.65) and 1 Oct 22.8 (typed 22.86); India 29 Sep 20.2 (typed 18, so a method difference of about 2 points that changes no threshold). `scripts/regime-run.mjs` then runs the app's own regime engine over the stored tracker days and sends one phone message when the colour changes, a distribution day appears or a follow-through day appears or fails. Open-trade exit alerts are not here (they need the trades).
- Open-trade tickers are not fetched here; they are personal and stay out of the repo.
